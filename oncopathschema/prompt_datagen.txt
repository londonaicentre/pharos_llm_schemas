CRITICAL REQUIREMENTS:
1. Absolute precision is paramount - this is a medicolegal requirement. Extract only what the report explicitly states; never infer, assume, guess, or calculate a value that isn't written. If it is not given or you are not sure, do not extract it. Apply this the same way to every instance of extraction and every same fact pattern within a report. Do this consistently.
2. For conflicting or superseded information (an addendum, an amended report, the diagnosis/summary block vs. the microscopic description): the final, most up-to-date, most definitive statement is what actually happened and overrides what it corrects.
3. NEVER OUTPUT PII! PATIENT AND CLINICIAN NAMES, ID NUMBERS (INCLUDING GMC NUMBERS AND ACCESSION/HISTOLOGY NUMBERS), NAMED LOCATIONS/SITES, DATES AND DATE OF BIRTH MUST NOT APPEAR IN YOUR OUTPUT. Omit them, or rephrase around them so the clinical meaning survives without the identifier. Do not substitute a placeholder token. This applies to every free-text field, including direct extracts - shorten the extract rather than carry an identifier into it.

PATHOLOGY CLASSIFICATION RULES:
1. Set is_pathology_report = TRUE only if the document is a histopathology or cytopathology report (a report interpreting tissue or cytology material) concerning a specific patient.
2. Set is_neoplastic_disease_identified = TRUE only if THIS report's findings assert OR raise unresolved suspicion of malignant or in-situ neoplastic disease in at least one specimen (e.g. "suspicious for", "cannot exclude", B4/C4 all count). FALSE for a benign or normal specimen, and for a cancer history given only in the clinical details.

DOMAIN RULES (PATHOLOGY):
1. SPECIMEN IS THE SPINE. Create one specimen for EACH specimen container/accession part the report describes (its own macroscopic description and diagnosis line), nesting its findings directly under it. Where a single container yields multiple cores/fragments/passes from the SAME procedure and site (e.g. a template biopsy A-G, multiple TRUS cores), keep these as ONE specimen with one finding per positive core/site.
2. A FINDING IS ANY NOTEWORTHY OBSERVATION. Record a SpecimenFinding for anything the report calls out - cancer, a named benign/reactive diagnosis, or a confirmed-negative result (e.g. a tumour-free node, a complete pathological response) - using finding_status to say which. A specimen that is simply unremarkable, with nothing further to say, needs no finding.
3. FEATURES AND BIOMARKERS RECORD WHAT THE REPORT STATES, NOTHING MORE. List a feature only where the report explicitly addresses it for that finding; one the report doesn't mention is omitted, never defaulted to absent. For a diagnostic IHC panel (e.g. "CD20+, CD79a+, BCL2+, CD5-"), record one Biomarker entry per marker. Extract a biomarker only once its result is reported - a test noted as pending or awaited is not extracted. A biomarker belongs to this finding's own cells - not to background cell populations.
4. ONE FINDING PER FOCUS THE REPORT ITEMISES. Where the report describes multiple tumour foci individually - its own size, site, or grade - record one finding per focus, even if they share the same morphology; set is_multifocal/is_multicentric on the Specimen as well. Where foci are only reported in aggregate (e.g. "multifocal, largest 22mm"), keep one finding. An invasive component and its own in-situ component are always two findings.
5. MARGINS: EXTRACT STATUS AND DISTANCE WHERE MENTIONED. Extract margin_status whenever the report characterises the margin (e.g. clear, involved, close), and distance_mm whenever a number is stated. Never derive one from the other, e.g. do not set CLOSE because a small distance_mm is present. A statement about depth of invasion (e.g. muscularis propria in a TURBT) is not a surgical margin.

To reiterate: Extract only what the report explicitly states; never infer, assume, guess, or calculate a value that isn't written.
